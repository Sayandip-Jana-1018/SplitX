Demo day

SplitX, live on AWS

A merge becomes a signed release, GitHub announces it, Jenkins verifies and deploys it on EKS behind CloudFront, and the room's phones drive the autoscaler. Every number on screen is read live from the tool that owns it. The full runbook is docs/DEMO_DAY.md.

The story, through /ops

  1. The release on main

    The top card: the commit, CI passed, then scanned, signed and attested, and the image digest.

    Built once by GitHub Actions and scanned by Trivy. Signed keyless with cosign, so there is no key to leak. The SBOM and the vulnerability report are attested to the image.

  2. Join the demo

    The QR code. Everyone opens /scale and plans a trip.

    Each answer names the pod that served it. Your phones are the load.

  3. The tools

    GitHub Actions, CodeQL, Trivy, Dependabot, SonarQube Cloud, Jenkins and Vercel, each with its own verdict.

    Nothing here is typed in by hand. Where a tool can't be read, the page says why.

  4. Pipeline and deliveries

    The release's jobs, then each environment's newest deployment: kind, eks and Production.

    A merge becomes a GitHub deployment. GitHub's signed webhook reaches Jenkins through CloudFront. Jenkins checks the webhook's signature and the image's before it deploys, and rolls back anything that doesn't come up.

  5. The cluster

    The nodes in two zones, the pods with their digests, the autoscaler, and Kyverno's admissions.

    An image our release workflow didn't sign can't run here, whoever asks.

  6. The traffic lab

    Start 30 plans a second for 180 seconds. Watch requests, p95 and errors, and the pods climbing from 2 towards 10.

    When a pod has nowhere to go, the Cluster Autoscaler adds a fourth node. Load is shed on purpose rather than queued until pods fail.

  7. Alerts, logs, evidence

    The alerts (none but Watchdog), the app's log with request IDs, and each deployment's evidence in Nexus.

    The SBOM, the vulnerability report and the deployment record are each checked with cosign before they are stored.

  8. AWS

    The CloudFormation stacks and their drift, EKS and its add-ons, CloudFront, and the budget.

    No workflow holds an AWS key. The roles are assumed through GitHub's OIDC, bounded, and only this one environment may build.

If something breaks

  • red pre-flight item Its text names the fix. After fixing it, run AWS verify.
  • aws-up failed The failed step says why: a missing secret, the webhook, or the quota. Fix it, and run AWS up again. It picks up where the platform is.
  • AWS is unavailable Show the newest green Kind end-to-end run: the same platform, every verifier's table on its summary page. Then the rehearsal's recording.
  • No network in the room Play the rehearsal's recording.
  • Always there The app at splitsj.vercel.app, and /ops there, with the pipeline half.
